## 1. 概要・プロダクトコンセプト

**おやごころ**は、家族が数年〜20年にわたり記録を書き、設定した「開封日」に届ける **家族の20年タイムカプセル** サービスである。

「親→子供への一方通行」設計ではなく、**思想を強制しない、設定で柔軟に多様な使い方へ対応するプロダクト**として設計する。シングル親が1人で使っても、夫婦で使っても、祖父母を加えた3世代で使っても自然に機能する。配信先も「子供に届ける」「夫婦だけの記録にする」「親友も含める」など、メールアドレスとタグの組み合わせで自由に設定する。

### 1.1 コアフェーズ（体験の骨格）

| フェーズ | 体験 |
|---|---|
| **書く（数年〜20年）** | 参加者それぞれが気が向いた時に書く。**書きっぱなし**設計（見返さない） |
| **封印（普段の状態）** | 他の参加者の記録は、書かれてから**1週間だけ**読める。1週間後は開封日まで封印 |
| **開封（任意 or 開封日到来）** | 参加者の誰か1人が開封ボタンを押すか、設定した開封日に自動配信 |
| **開封後の世界** | 全員が全期間の記録を自由に閲覧可能（不可逆） |
| **配信** | 開封日に、登録した全配信先メールアドレス宛てに内容が届く |

### 1.2 プロダクトの精神的支柱（創業者の言葉）

> **「本当は、親の気持ちは子供に見せてはいけないものだと思う」**
> **「子育てを終えた夜、こっそり妻と20年間振り返るもの」**
> **「ただ人によってはその気持ちを子供に共有したい人もいるだろうから、そこは人それぞれで良い」**

この言葉が、おやごころの**全機能・全ルールの判断基準**である。「思想は強制せず、設定で柔軟に」というプロダクト哲学の根本であり、機能設計に迷った際の拠り所とする。

## 2. 社会契約宣言

本サービスは、家族が数十年にわたって積み上げた感情的記録を、**ユーザーが設定した開封日まで＋それ以降5年（PDF配信履行期間）にわたって安全に保管・配信する社会的責任**を負う。以下をユーザーおよび社会へ公約する。

- **サービス継続保証**: サービス終了が避けられない場合、最低12ヶ月前にユーザーへ通知する
- **データ完全エクスポート権**: いつでも JSON + Markdown + PDF 形式でデータを取り出せる（全プラン無料）
- **配信意志の尊重**: 設定した配信は、参加者の死後・退会後であっても履行される
- **削除された参加者の記録は、家族の財産として保持される**: 参加者がアカウントを削除・退出しても、その人が書いた記録は保護され、開封日に配信される
- **データ売却禁止**: ユーザーの記録データを第三者へ売却・提供しない
- **AI学習への利用禁止**: ユーザーの記録を生成AIの学習データとして利用しない

この宣言はアプリ内の利用規約・FAQ に常時掲示し、プロダクトアップデートによって後退させない。

## 3. コアフェーズと状態遷移

状態機械は 4 つのエンティティに分かれる。バックエンドはこれらの状態と遷移条件を権威として保持する。

### 3.1 ユーザー状態

```
[未登録]
   │ サインアップ（Firebase Auth: Google / Apple Sign-In）
[無料プラン] ── 月5件・テキストのみ・参加者2人・配信先5メアド
   │
   ├─ [トライアル中(trialing)] ── 7日間、有料機能フル開放
   │        │ 7日経過・初回課金
   │   [有料プラン(active)] ── 月200件・写真/音声可・ストレージ5GB付帯
   │        │
   │        ├─ [解約予定(canceled・期限内)] ── auto_renew=OFF。期限までは有料権利を維持
   │        ├─ [猶予期間(in_grace_period)] ── 課金リトライ中。権利あり
   │        ├─ [保留(on_hold)] ── 課金失敗継続。権利なし → free にキャッシュ降格
   │        └─ [失効(expired)] ── 権利喪失（返金・期限切れ）→ free 降格
   │
   └─ [退会] → [データ5年保持] → [完全削除]
              ※開封予定がある場合は配信実行後に削除
```

- **エンタイトルメント（有料機能を使える）判定**: `status IN ('trialing','active','in_grace_period')` は無条件で権利あり。`canceled` は現在の課金期間の終端まで権利あり。`on_hold` / `expired` は権利なし。真実の源はストア（Apple/Google）であり、当方 DB はミラー（詳細は §6）。

### 3.2 記録（レコード）状態

```
[入力中（下書き＝端末ローカル保存のみ）]
   │ 保存（サーバ保存は確定保存のみ）
[保存完了]
   ├─ 自分の記録 ────────────── 常時全文閲覧可（封印対象外）
   └─ 他参加者から見た状態:
        [1週間ウィンドウ中] ── 全文閲覧可 + 残り日数カウントダウン
              │ ★F: 投稿日翌日0時（JST）起算で7日間経過
        [封印中] ────────────── 内容非表示。「封印中」とロック日時のみ
              │ 開封イベント（任意開封 or 開封日到来）
        [開封済み] ───────────── 全員が全文閲覧可（不可逆）
```

- **削除は全状態で不可**。書いた時点で確定（誤字含む）。編集も不可。下書きは端末ローカルのみでサーバには残さない。

### 3.3 参加者状態

```
[招待送信済み] ── 招待リンク未承諾
   │ 招待リンクから参加
[アクティブ参加者] ── 全機能を同権限で利用可
   │ 削除（他参加者による削除 or 自己退出）
[削除済み] ── アクセス不可。記録は「元参加者」表記で保持・配信
```

### 3.4 タイムカプセル（グループ全体）状態

```
[封印モード（書く期間）] ── デフォルト状態
   ├─ 任意開封: 参加者の1人が開封ボタンを押す（二段階確認）
   └─ 自動開封: 開封日（0時 JST）到来をシステム検知
        │
   [開封済みモード] ── 全員が全期間を閲覧可（不可逆・再封印不可）
```

### 3.5 重要な起算・境界ルール（★F）

- **1週間ウィンドウ**: **投稿日翌日0時（JST）起算で7日間**。計算は常に JST（UTC+9）基準。7日目の 23:59:59 JST まで閲覧可、翌 0:00:00 JST から封印。海外在住者にはデバイスのローカルタイムで表示変換するが、**計算基準は JST 固定**。
- **1週間ウィンドウ中に開封日が到来した場合**: 開封日が優先。ウィンドウ中の記録も含め全記録が即座に開封状態へ遷移。
- **開封は不可逆**: 二段階確認後、再封印不可。

## 5. 重要な業務ルール

### 5.1 届け先トグル（記録ごと）

| 値 | 既定 | 配信時の動作 |
|---|---|---|
| `all`（全員に届ける） | ✅ | 全配信先メアドへ届く |
| `parents_only`（内輪のみ） | オプション | 「内輪のみ」タグのメアドだけへ届く |

### 5.2 配信先タグとフィルタ

配信先メアドは追加時にタグ選択必須（既定 `all`）。無タグ状態は許容しない。

| メアドのタグ | 受け取る記録 |
|---|---|
| `all`（全員） | 届け先 `all` の記録のみ |
| `parents_only`（内輪のみ） | 届け先 `all` の記録 + `parents_only` の記録 |

- **プライバシー保護**: 配信対象が0件になる記録（例: 全メアドが `all` タグで届け先 `parents_only` の記録）は**配信しない**。ログにエラー記録し、該当状態時は配信先管理画面で警告バナーを表示。

### 5.3 参加者・完全民主制

- 創設者・招待者すべて同権限（管理者/一般の区別なし）。全参加者が招待・削除・開封日変更・開封を実行できる。
- 自己退出可能。退出しても自分の記録は保持・配信。再参加は不可（新規アカウント扱い）。
- **削除された参加者の記録**は保持され、アーカイブ内で **「元参加者」表記**（実名は伏せる、★I）。配信メール内では「家族の一員より」等で匿名化。削除者のメアドが配信先に登録されていれば配信先からも自動除外。

### 5.4 開封の二段階確認

1. 第1段階: 「タイムカプセルを開封しますか？ この操作は取り消せません」
2. 第2段階: 確認のため「開封」と入力させる
3. 実行後: 全参加者を即座に開封済み状態へ遷移 + 全配信先へ「開封されました」通知。キャンセル不可（不可逆）。

### 5.5 月次件数上限とソフトブロック

- **無料**: 月5件。6件目を書こうとした瞬間に**ソフトブロック**（記録は保存されない）。翌月0時 JST にリセット。
- **有料**: 月200件。180件目で警告、201件目でブロック（翌月リセット）。
- ソフトブロックからの導線: 「7日間無料トライアルから始める」／「アップグレード」／「来月まで待つ」。

### 5.6 エッジケースの確定挙動

- **全参加者削除（凍結状態）**: 最後の参加者が退出すると参加者0人の「凍結状態」。記録は保持・配信予定を維持し、開封日のみ自動実行。凍結状態への新規参加者追加手段はない（セキュリティ担保）。
- **開封後の参加者追加**: 不可（開封後は「読む期間」）。ただし配信先メアドの追加・手動再送は可能。
- **開封日変更**: 全参加者へ変更通知（プッシュ・メール、変更者名付き）。開封後は変更不可。
- **配信失敗（バウンス）**: 24時間以内に自動リトライ×3。失敗後は当該メアドを「配信一時停止」にフラグし、次回配信から除外。登録者へ通知。

課金は **Apple App Store IAP + Google Play IAP** で行う。決済・トライアル・課金リトライ・猶予期間の**時計はストア側が管理**し、当方 DB はストア通知＋検証 API で取得した状態を保存する**ミラー**である。

### 6.3 追加ストレージ（買い切り・消費型 IAP）

- **10GB追加 = ¥1,500 買い切り**（20年保管込み・取り出し料金込み・追加/取り消し不可）。
- 基本プランの 5GB が残る間は購入不要。使い切り時に購入を提案。

### 6.4 ストレージ消費の定義

- **テキスト**: 消費に含めない（**無制限**）。
- **画像・音声・動画**: 実バイト数を消費にカウント。画像は自動圧縮（WebP変換・最長辺1,920pxリサイズ、例 5MB→約500KB）。
- **有効追加ストレージ量**の集計: 返金無効化（`revoked_at`）されておらず、有効期限（購入+20年）内の購入分のみを合算。

### 6.5 7日間無料トライアル

- トライアル期間: 7日間。トライアル中は有料機能フル開放。
- 開始・課金はストア側で処理（ストアの導入オファー＝無料期間として構成）。
- 3日前・1日前にリマインダー（プッシュ+メール）。トライアル終了で自動的に有料課金へ移行。

### 6.6 転換トリガー（コンバージョン）

- **月6件目を書こうとした瞬間**（無料月5件上限）← 最も強力なソフトブロック
- **写真/音声を添付しようとした瞬間**（無料はテキストのみ）
- **有料ユーザーが 5GB を使い切った瞬間** ← 追加ストレージ ¥1,500 への誘導（80%到達時に事前通知）

### 6.7 購読状態同期（ストア通知 → DB ミラー）

真実の源はストア。通知は「変化があった合図」であり、当方は検証 API を叩いて状態を取り直す。

- **Apple（App Store Server Notifications V2）**: 署名付き `signedPayload`(JWS) を受信 → x5c 証明書チェーンを Apple Root CA まで検証 → `notificationType`+`subtype`+transaction/renewal 情報から状態を導出。購読の不変キーは `originalTransactionId`。
- **Google（RTDN / Pub/Sub）**: 通知本文は購読状態を含まない。受信を合図に `purchases.subscriptionsv2.get(purchaseToken)`（消費型は `purchases.products.get`）で権威状態を取得。`purchaseToken` は再購読・アップグレードで**ローテーション**するため、`linkedPurchaseToken` 連鎖を追跡し最新値を保持する。
- **ユーザー紐付け**: 購入時にアプリが `users.id`(UUID) を Apple `appAccountToken` / Google `obfuscatedExternalAccountId` として渡す（初回紐付けヒント）。権威は「購読識別子 → user_id」の DB 逆引き。
- **冪等・順序保証**: プラットフォーム別識別子の UNIQUE で冪等 UPSERT。加えて直近通知時刻の**単調ガード**で、遅延・再送された古い通知による状態の巻き戻しを防ぐ。消費型は購入識別子の UNIQUE + ON CONFLICT DO NOTHING で二重付与をゼロにする。
- **sandbox/production 混線防止**: `environment` を保持し、本番エンタイトルメント判定は `production` を要求。

### 6.8 IAP 特有のユーザー向け挙動

- **猶予期間(in_grace_period)**: 課金リトライ中もサービス継続（権利あり）。
- **保留(on_hold)**: 課金失敗が続き権利喪失 → 無料プランへ降格。復旧課金で復帰。
- **リストア購入**: 別端末での復元は同一購読識別子で冪等に処理。**別ユーザーが同一識別子を主張した場合は競合**（家族共有・中古端末等）として拒否し、サポート対応に回す。
- **返金**: サブスクは Apple `REFUND` / Google `VOIDED_PURCHASE` を受けて権利剥奪 → 無料降格（行は監査目的で保持）。消費型ストレージは返金され得るため `revoked_at` で無効化し有効量から除外（行は物理削除しない）。

### 6.9 解約防止

- 「開封日に届く」体験そのものが最大の解約抑制装置。解約後も**既存記録は開封日に確実に配信**され、新規記録の追加のみ停止する旨を明示。

## 7. 受け入れ基準（AC）

| ID | シナリオ | 期待結果 |
|---|---|---|
| AC-01 | 無料ユーザーが5件記録する | 正常に保存される |
| AC-02 | 無料ユーザーが6件目を書こうとする | ソフトブロック表示、記録は保存されない |
| AC-03 | 有料プランに加入（IAP課金完了・検証成功）する | 即時に月200件まで記録可能になる |
| AC-04 | 参加者Aが記録を保存する | 参加者Bは1週間ウィンドウ中に全文閲覧可能 |
| AC-05 | 1週間ウィンドウが終了する（投稿翌日0時JST起算・7日後0時） | 参加者Bから見て「封印中」表示に切り替わる |
| AC-06 | 参加者の1人が開封ボタンを押す | 二段階確認後、全参加者が即座に開封済み状態へ遷移 |
| AC-07 | 開封日が到来する | 全配信先メアドへ正常配信される |
| AC-08 | `parents_only` 記録が開封日に配信される | 「内輪のみ」タグのメアドにのみ届き、「全員」タグには届かない |
| AC-09 | 参加者を削除する | 削除された参加者の記録が「元参加者」表記でアーカイブに残る |
| AC-10 | 削除された参加者の記録が開封日に配信される | 他の記録と同様に配信対象に含まれる |
| AC-11 | エクスポートを実行する | 3形式（PDF/JSON/Markdown）が5分以内に生成される |
| AC-12 | 有料ユーザーが月200件目を書く | 正常に保存される（180件目で警告表示） |
| AC-13 | 有料ユーザーが月201件目を書こうとする | 「来月リセット」表示・保存ブロック |
| AC-14 | 有料ユーザーが解約（ストアで自動更新OFF）する | 期限までは有料権利を維持し、期限到来で無料へ降格 |
| AC-15 | 開封日変更を実行する | 全参加者へ変更通知（プッシュ・メール）が届く |

## 8. 非機能要件・技術スタック

### 8.1 データ保全

- **保管期間**: ユーザー設定の開封日まで + それ以降5年（PDF配信履行期間）。
- **ストレージ**: AWS S3 + Glacier（長期保管最適化）。5年ごとに媒体移行計画を策定。
- **フォーマット保証**: 写真は JPEG/HEIC→JPEG（圧縮）保存、音声は MP3/AAC→MP3、PDF は PDF/A-1b 準拠。
- **バックアップ**: 日次自動バックアップ・地理的冗長。年次データ完全性監査（SHA-256 ハッシュによる改ざん検知）。

### 8.2 セキュリティ

- 通信: TLS 1.3 以上。保存データ: AES-256 暗号化。
- 認証: **Firebase Auth**（Google Sign-In + Apple Sign-In）。バックエンドは Firebase ID Token を検証するのみ。Apple の relay email（`@privaterelay.appleid.com`）も受け付ける。
- PII: 個人情報保護法・GDPR 準拠。退会時の匿名化対象は `display_name / email / firebase_uid`。IAP 購読識別子は PII ではないため §6.8 の返金・保持方針に従う。

### 8.3 可用性

- SLA: 99.9%（月次ダウンタイム44分以内）。
- 配信処理: 冗長化バッチ。配信失敗時は24時間以内に自動リトライ×3。

### 8.4 パフォーマンス

- 画面ロード: 2秒以内（モバイル回線）。
- エクスポート生成: 5分以内（1,000レコード規模）。
- 同時配信: 年間最大10万件の開封日配信を処理できるスケール設計。

### 8.5 技術スタック

| 領域 | 採用技術 |
|---|---|
| フロントエンド | **iOS / Android ネイティブアプリ** |
| バックエンド | **FastAPI**（Python） |
| DB | **PostgreSQL（Neon）**（サーバーレス Postgres、ブランチング対応） |
| ORM / マイグレーション | **SQLAlchemy（async）** + **Alembic** |
| 認証 | **Firebase Auth**（Google / Apple Sign-In。ID Token 検証） |
| メール配信 | **Resend**（送信元 `noreply@lydear.com`。バウンス Webhook 対応） |
| ストレージ | **AWS S3**（Standard + Glacier Deep Archive） |
| 課金 | **Apple App Store IAP** + **Google Play IAP**（ASSN V2 / RTDN で状態同期） |
| スケジューラ | バッチ（開封日到来検知・トライアル終了・配信リトライ等） |
